# Руководство разработчика

## Стек и запуск

- React + TypeScript.
- Vite.
- CSS без отдельной дизайн-системы или CSS-in-JS.
- Иконки: `lucide-react`.

```bash
npm install
npm run dev
npm run build
npm run preview
```

Dev-сервер привязан к `127.0.0.1`. Production-результат создаётся в `dist/`.

## Архитектура

### `src/App.tsx`

Содержит:

- верхнеуровневую машину экранов `map | lesson | lessonComplete | moduleComplete`;
- состояние текущего упражнения, попыток, результатов и повтора ошибок;
- аудио и звуковую обратную связь;
- компоненты режимов упражнений;
- DEV-навигацию;
- мобильный Fullscreen hook.

Файл намеренно компактный и во многих местах записан однострочно. При точечных правках не форматировать весь файл без необходимости: это затруднит review и может затереть пользовательские изменения.

### `src/lessonData.ts`

Главный источник контента урока. Тип `Exercise` содержит:

- `id` — номер упражнения;
- `mode` — `fill`, `image`, `assemble`, `speak`, `pairs` или `chatbot`;
- `instruction` — заголовок задания;
- `prompt` — татарский пример;
- `audio` — путь к аудио;
- `choices` / `tokens` — варианты ответа;
- `correct` — строка или упорядоченный массив правильных ответов;
- `answerLabel`, `explanation`, `theory` — обратная связь и теория.

При изменении порядка упражнений проверить соответствие `uprN.mp3`, персонажа и прогресс-бара.

### `src/styles.css`

Содержит базовую раскладку 390 × 844, все состояния, анимации и media queries. Порядок правил важен: файл содержит поздние уточняющие селекторы, которые могут перекрывать ранние. После CSS-изменения проверять итоговый каскад, особенно для `.matched`, `.disabled`, `.fill-sentence`, `.choice-zone` и мобильных media queries.

## Мобильная адаптация

Основной контрольный размер — 390 × 844 px. Дополнительно проверять короткие viewport около 390 × 640 и 390 × 540.

`MOBILE_ADAPTIVE_UI` управляет мобильным экспериментом. При `false` класс `.mobile-adaptive` не добавляется и Fullscreen не запрашивается.

Не полагаться на `100vh`: использовать `100dvh` для мобильного браузера. Учитывать `env(safe-area-inset-top)`.

Автоматический Fullscreen без жеста запрещён браузерами. Текущая реализация запрашивает его после первого `pointerup` и молча продолжает работу, если API недоступен.

## Проверка изменений

Минимальный чек-лист:

1. `npm run build`.
2. Главный экран на 390 × 844.
3. Изменённый тип упражнения на первой и второй попытке.
4. Появление кнопки результата не должно сдвигать варианты ответа.
5. Перелетающие элементы должны завершать анимацию в нужном плейсхолдере.
6. Аудио должно запускаться и останавливаться без необработанных Promise errors.
7. Проверить viewport с небольшой высотой.
8. `git diff --check` и `git status --short`.

Известные безопасные предупреждения сборки: Vite/Rolldown может сообщать, что директива `"use client"` в модулях `lucide-react` не сохраняется. При exit code 0 это не блокирует сборку.

## Git и выпуск

Репозиторий: `https://github.com/iayupov/atm`.

```bash
git status --short
git diff --check
git add <изменённые исходники>
git commit -m "Описание изменения"
git push origin main
npm run build
```

`dist/` не коммитится. Для хостинга загружается содержимое `dist/`. При необходимости архив создаётся из `dist/*`, а не из самой родительской папки.

Production-сайт `atm.teorius.ru` выкладывается по SSH. Полная инструкция, параметры сервера, безопасная атомарная замена и откат описаны в [ssh-deployment.md](ssh-deployment.md).

Не добавлять в Git:

- `node_modules/`;
- `dist/`;
- `*.zip`;
- `*.tsbuildinfo`;
- временные скриншоты и профили браузера.

## Безопасное редактирование

- Сохранять существующие пользовательские изменения и не выполнять `git reset --hard`.
- Для локальных правок использовать минимальные патчи.
- Не удалять ассеты, если они кажутся неиспользуемыми, без проверки всего потока.
- После изменения общей логики проверить все режимы упражнений, использующие компонент.
- Новый UX, не описанный пользователем или документацией, помечать `TBD`, а не додумывать.
